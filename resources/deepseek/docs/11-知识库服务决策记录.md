# 知识库服务 · 决策记录（ADR-001）

> 状态：已决策，待执行
> 日期：2026-10-27
> 决策人：项目负责人

## 1. 决策

租用**一台 Linux 服务器**，在其上完成：

1. **知识存储**（向量索引 + 元数据）
2. **Embedding**（本地 bge 或 API）

并将**项目后端**与**知识库服务**都部署在这台服务器上（Docker Compose 编排）。

## 2. 架构

```
前端(Vue)
  ↓ HTTP
项目后端(Fastify, :3000)
  ↓ HTTP（容器内网）
知识库服务(FastAPI, :8000)
  ├─ 向量存储（LanceDB / Qdrant）
  └─ Embedding（bge 本地 / API）
```

- **知识库服务**：对外只暴露检索接口 `/search`（+ `/index` 建库），**不暴露公网**
- **项目后端**：接前端请求 → 调 `/search` → 拿 TopK → 拼 prompt → 调 DeepSeek
- **Nginx**：托管前端静态 + 反向代理 `/api`

## 4. 检索策略

1. **元数据硬过滤**（场景/情绪/构图/色调/风格/语言）
2. **位置结构相似**（区域 Jaccard + 重心距离 + 面积接近度）
3. **语义相似**（向量 cosine）
4. **融合重排**：`0.3·元数据 + 0.4·位置 + 0.3·语义`
5. **TopK**：初筛 5-8，融合后 2-3

## 6. 部署形态

- **一台 2核4G 服务器**（Ubuntu 22.04）
- `docker-compose.yml` 编排：`backend` + `kb` + `nginx`
- 数据卷挂载：`/data`（字体、灵感库、知识 JSON）
- 环境变量：`DEEPSEEK_API_KEY`、`EMBEDDING_KEY`（如用 API）

## 7. 本地开发环境说明

- 开发在 Mac（ARM64）；服务器为 x86_64
- 原生依赖（LanceDB / onnxruntime）在 Mac 上存在 pnpm 解析 / 代码签名问题，**不作为本地阻断项**
- 本地用「API embedding + 内存索引」兜底，服务器上用「bge + 向量库」
