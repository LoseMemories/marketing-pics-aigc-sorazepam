# 产品 PRD · 营销照片 AIGC（阶段版 v0.2）

- 版本：v0.2（2026-10-26）
- 作者：产品 / 工程联合
- 状态：原型已跑通，进入「效果攻坚 + Agent 化」阶段
- 关联文档：`01-技术方案.md`、`02-局限与增强路线.md`、`04-数据契约.md`

---

## 1. 一句话定位

把一张**真人实拍照片（含苹果实况 Live Photo）**，自动变成可直接发布的**营销画面**：一句可信文案 + 一套有克制的排版与动效，并给出可解释的设计理由。

长期目标不是「修图工具」，而是**营销博客数字人 Agent** 的视觉产出臂：它理解素材的真实故事、理解品牌与受众、理解投放场景，然后自己出稿、自己审、自己改。

## 2. 目标用户与场景

| 用户 | 现状痛点 | 我们要给的 |
|---|---|---|
| 独立博主 / 小店店主 | 拍完好照片但不会排版，套模板又很「模板感」 | 一键出稿：文案来自自己的真实故事，版式不土 |
| 品牌内容运营 | 一次活动几十张素材，人工排版产能不足 | 批量化、可控的品牌一致性 |
| 数字人 Agent（长期） | 只能生成文字，不能产出视觉资产 | 可被 Agent 调用的「视觉生产 skill」 |

**非目标（本阶段明确不做）**：修图/美颜、生成式重绘主体、视频剪辑、跨平台一键发布。

## 3. 现有能力（已完成并验证）

### 3.1 主流程（4 步，工作台内完成）

1. **画面理解**：视觉模型输出主体（含 20 点多边形避让边界、**0–100 主体价值分**）、文字安全区（含底色）、主色调、风格标签、风险项。
2. **L1 构图决策（纯代码）**：按主体像素覆盖率生成 3×3 决策网格，算出「主文字承载区 / 收尾小字承载区」，并给出候选配色（含对比度）。
3. **L2 设计师（LLM）**：输出 `DesignSpec` —— 文案层级（kicker/headline/subline/paragraph/meta）、锚点、对齐、字号比、字重、字体族、3D 文字、变形、运动路线、入场/循环动效、光效与滤镜、调色板、节奏。
4. **L3 Canvas 解算（纯代码）**：把语汇变成坐标与时间轴：10% 边距、文字组堆叠、重叠消解、特效避让文字、时长映射。
5. **渲染**：Canvas 2D 双模式 —— 静态封面（= 所有效果的最终形态）+ 长按播放动效。

### 3.2 文案质量控制

- 文案**唯一依据**是运营写的「照片事实背景」（`samples/copy-sources/*.md`），不允许编造品牌/价格/日期。
- 三条禁令 + 18 条反例 + 18 条正例 + 10 组「反例→正例」改写对照（`prompts/04-copy-rules.prompt.md`）。
- 代码兜底：文案里出现「描边 / 镭射 / 俯拍 / 色调 / 反差 / 层次感…」等 40+ 个词，判定为「设计说明或图片描述」，会被摘掉并回退重试。

实测样例（曼谷演唱会照）：

```
眉标 THE WEEKND / Hero 曼谷 · 第二场 / 副标 亚洲巡回 · 泰国曼谷站 / 信息行 2026.10.12
```

### 3.3 动效体系（12 个可执行动效）

- 文字入场 9 种、循环 2 种、光效/滤镜 6 种（含 `glow-mask` 树影光斑、`soft-focus` 柔光、`strobe` 频闪、`laser-overlay` 潮流滤镜）。
- 「文字与主体重叠」：重叠处用饱和度渐变混色，主体不被盖死、文字不缺角。
- 特效是**可选项**：提示词明确要求按「故事背景 + 主色调 + 主体色 + 背景复杂度」判断，通常 0–2 个。

### 3.4 交互

- 步骤条严格对应运行状态，可回退重跑。
- L2 可手改文案/锚点/字号/动效；**改动不上屏，点「重新渲染」才更新**（避免边打字边抖）。
- 主体标签带分数，低于 60 分默认不选中。

## 4. 用户旅程（现状态）

```
选素材 → 画面理解(≈20s) → L1 构图(瞬时) → L2 设计(≈15–20s) → 手改文案 → 重新渲染(≈15ms) → 长按预览动效
```

## 5. 当前阶段的局限（重点）

> 这一节是本次交接的核心：**上线验证后确认，只靠大模型 + 规则引擎，效果天花板是「不出错的模板感」**。

### 5.1 视觉与合成层

| # | 局限 | 现象 |
|---|---|---|
| P1 | **只做「叠加」不做「合成」** | 画面 = 原图 + Canvas 叠加文字/光效。不能换背景、不能补光、不能把主体移进更好的留白（构图不动，只能迁就照片） |
| P2 | **排版靠估算，不靠字体度量** | 文字盒宽高用「字符数 × 字号」估，中文/英文/数字混排、字距、斜体旋转都会偏，只能靠 10% 边距与推挤兜底 |
| P3 | **抠图/避让边界是模型给的粗轮廓** | 20 点多边形，粗糙；描边效果沿多边形走线，人物边缘复杂时会显得「抖」 |
| P4 | **没有字体资产** | 只用系统字体（PingFang / system-ui），无法做品牌字体、装饰字、可变字重，也谈不上字体授权管理 |
| P5 | **滤镜是程序化色块** | 光斑/柔光/频闪都是 Canvas 画出来的近似效果，不是真正的光学合成（如树影投射到主体上的明暗） |
| P6 | **无导出管线** | 只有浏览器内的 Canvas，没有 PNG/MP4 导出、没有多尺寸/多平台规格（小红书 3:4、故事 9:16、封面 4:3） |

### 5.2 智能与知识层

| # | 局限 | 现象 |
|---|---|---|
| P7 | **没有设计知识库** | 模型的审美来自通用预训练，「好版式」不可检索、不可复用、不可解释。所有约束写在提示词里，难以规模化沉淀 |
| P8 | **单次生成，无候选比较** | temperature=0 单发，没有 best-of-n、没有自评打分、没有把「上一次被人工改成什么样」学回来 |
| P9 | **设计师没有工具** | L2 只能「说」，不能「量」：无法调用字体度量、对比度检测、版面冲突检测、试渲染看效果 |
| P10 | **没有品牌资产与一致性** | 不知道该商家的品牌色/字体/口吻/禁用词；多张图之间风格不统一，做不了账号级一致性 |
| P11 | **文案只有一层事实** | 只能读一段运营写的资料，不能读商品库/SKU/活动日历/历史爆款文案 |
| P12 | **没有多模态理解闭环** | 分析结果（主体/安全区/色调）不可被人工校正后回流，误差会一直重复 |

### 5.3 工程与运营层

| # | 局限 | 现象 |
|---|---|---|
| P13 | 同步单进程 | 分析 20s / 设计 18s 全在请求里等，没有队列、没有并发隔离、没有断点续跑 |
| P14 | 无观测与成本核算 | 没有 token 成本、失败率、重试率、人工改动率等指标面板 |
| P15 | 无审核与合规 | 真人肖像、品牌名、价格、功效表述没有审核通道与免责声明 |
| P16 | 无可复现基线 | 没有「素材集 + 期望输出」的评测集，改一版提示词只能靠人眼看看 |

## 6. 目标态产品形态（下一阶段）

### 6.1 从「工具」到「数字人 Agent」

```
[选题/素材] → 内容策划 Agent（故事骨架 + 平台策略）
            → 视觉设计 Agent（L2 升级：带 skill + 知识库 + MCP 工具）
            → 生成执行（L3 + 合成 MCP + 导出）
            → 自评 Agent（多模态打分 + 规则校验）→ 不过则回到设计
            → 人工一键确认 → 发布
```

关键差异：**Agent 会「查资料、量数据、试渲染、自我否定」**，而不是一次性输出。

### 6.2 三个必须新增的能力（详见 `02-局限与增强路线.md`）

1. **多模态设计知识库**：把优秀营销版式（图 + 文本 + 动效 JSON）做成可检索资产，按「场景/调性/主体类型/平台」召回，作为 L2 的 few-shot 与约束来源；并能把「人工最终稿」沉淀回库。
2. **设计师 Skill**：把能力做成可被模型调用的工具（字体度量、对比度校验、版面冲突检测、快速试渲染、知识库检索、品牌资产查询），让模型具备「测量感」，而不是靠语义猜。
3. **照片合成 MCP**：分割/抠图、光照匹配、投射阴影、生成式修补（inpainting/outpainting）、背景处理、主体重定位。让系统从「往照片上贴字」升级为「真的做出一张图」。

## 7. 需求分期

### P0 · 效果攻坚（建议 2–3 周）
- 字体真实度量替换估算（P2）
- 多候选生成（3 候选）+ 规则打分 + 取最优（P8）
- 评测集：≥50 张素材 + 人工认可的参考输出，跑通回归（P16）
- 导出 PNG（单尺寸）与基础观测指标（P6 部分 / P14）

**验收**：同一素材 3 候选里，至少 2 个「不需要人改文案」，1 个「不需要人改版式」；导出分辨率与前端预览一致。

### P1 · 知识库 + Skill（建议 4–6 周）
- 设计知识库 v1（≥300 组优秀版式，向量 + 结构化标签），L2 检索注入 few-shot（P7）
- 设计师 Skill v1：`measure_text` / `check_contrast` / `detect_layout_conflict` / `render_preview` / `query_design_kb`（P9）
- 品牌资产（色/字/口吻/禁用词）注入（P10）
- 多模态自评 Agent（版面/可读性/主体遮挡/文案合规 4 维打分）（P8）

**验收**：在评测集上，人工改动率下降 ≥40%；同账号 5 张图风格一致性人工评分 ≥4/5。

### P2 · 合成 MCP + 导出（建议 6–8 周）
- 合成 MCP：`segment` / `matting` / `relight` / `shadow` / `inpaint` / `outpaint` / `composite`（P1/P3/P5）
- 视频导出（Canvas 逐帧 → ffmpeg → MP4 + 静态封面）（P6）
- 多尺寸/多平台规格批量导出
- 队列化与断点续跑（P13）

**验收**：能做「主体重定位 + 光影匹配」的成图；一条素材 30s 内出 3 尺寸成品。

### P3 · Agent 化（长期）
- 选题 → 文案 → 视觉 → 自评 → 发布 的编排（含记忆与人工干预点）
- 历史改动学习：把人工修改沉淀成偏好样本回灌 L2（P12）
- 合规审核通道与肖像/品牌风控（P15）

## 8. 成功指标

| 指标 | 定义 | 当前 | P1 目标 |
|---|---|---|---|
| 文案可接受率 | 人工未修改直接采用的比例 | 未测（主观约 50%） | ≥ 80% |
| 版式可接受率 | 人工未调整锚点/字号即采用 | 未测（主观约 40%） | ≥ 70% |
| 单图时延 | 分析 + 设计端到端 | 35–40s | ≤ 20s |
| 单图成本 | 模型 token 成本 | 约 0.01–0.02 元 | 持平或更低 |
| 重试率 | validator issues > 0 的比例 | ≈ 30% | ≤ 10% |
| 设计理由可读性 | concept 是否说得通（人评 1–5） | 3.5 | ≥ 4 |

## 9. 风险

| 风险 | 说明 | 对策 |
|---|---|---|
| 肖像权/品牌名 | 真人商业使用、无意中出现品牌 logo | 审核通道 + 禁用词表 + 人像模糊开关 |
| 文案事实性 | 模型仍可能编造 | 资料为唯一事实源 + 关键词拦截 + 人工确认门 |
| 字体授权 | 引入品牌字体后 | 字体白名单 + 授权元数据 |
| 效果提升随模型波动 | 换模型/换版本回归 | 评测集 + 版本化提示词 + 固定抽样回归 |
| 成本 | best-of-n 与自评会翻倍 | 分级策略：草稿 1 候选、终稿 3 候选 |
