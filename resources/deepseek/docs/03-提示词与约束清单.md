## 2. L2 提示词的六段结构

```
① 创作方向（运营给的风格期望）
② 照片的事实背景与想突出的信息  ← 唯一允许的文案依据
   + 「如何用这段资料」（事实可用、禁止编造、不要描述画面）
③ 文案能写什么/不能写什么（18 反例 + 18 正例 + 10 组改写对照 + 允许的信息类型）
④ 画面理解 JSON（含主色调、主体色、背景复杂度、主体价值分）
⑤ L1 构图结论 JSON（承载区、候选配色、设计理由）
⑥ 动效目录（文字入场 9 / 循环 2 / 光效与滤镜 6，每条含参数范围与枚举）
⑦ 输出要求（字数、锚点、字号比、字体、变形、路线、3D、配色）
⑧ 文案铁律 A/B/C
⑨ 动效不是必选项 D–I（按故事/色调判断、整幅滤镜最多 1 个、occlude 语义）
⑩ 返回 JSON 结构（含一份完整示例，示例里 occlude=false 避免诱导）
```

## 3. 文案红线（三条禁令）

1. **不描述图片本身**：视角、构图、光线方向、色调、材质反光、器材、景别。
2. **不写设计心思与手法**：反差、层次、留白、呼吸感、视觉重心、描边、压字（这些只进 `concept`）。
3. **不写主体/画面的基础特征**：衣服颜色款式、裤子、鞋、发型、镜头角度、整体色调；
   只有资料**明确要求**突出单品/穿搭/摄影时才允许，且必须挑资料提到的单品；「顺带提一句穿搭」不算要求。

**允许**：真实地点、季节节气、客观风格 tag（复古潮流/深秋）、资料里的商品类别/材质/工艺/卖点、情绪与场景结论、行动号召。

## 4. 代码侧的硬约束（与提示词互补）

| 约束 | 位置 | 值 / 行为 |
|---|---|---|
| 结构校验 | `design-spec.schemas.ts` | zod：字段类型、枚举、范围；`concept ≤ 160` 字 |
| 层数预算 | `design-spec.validator.ts` | blocks ≤ 5、effects ≤ 3 |
| 字数 | 同上 | headline 4–14；paragraph ≤ 30；其它 ≤ 40 |
| 锚点合法性 | 同上 | 只认 `textAnchor / secondaryAnchor / safeZone:<i> / free` |
| 偏移 | 同上 | `dxPct/dyPct` ∈ ±8 |
| 配色合法性 | 同上 | 必须来自 L1 候选；否则回退默认正文色 |
| 3D 文字 | 同上 | 仅 headline 可用 |
| 动效参数 | `motion-catalog.ts#clampParams/clampOptions` | 越界夹取、未知键丢弃、枚举回退默认，逐条记 issue |
| 设计说明/图片描述 | `design-spec.validator.ts#looksLikeDesignNote` | 40+ 关键词命中 → 记 issue 并从画面移除（headline 保留） |
| 主体评分门槛 | `frontend .../AiDesignPanel.vue` | `SUBJECT_SCORE_THRESHOLD = 60`，低于阈值的标签默认不选 |
| 重试回路 | `application/design-layout.ts` | issues > 0 时带 issues 再要一次，取 issues 更少者；最多 1 次 |

## 5. 改提示词的流程（必须遵守）

1. 改 `deepseek-design-assistant.ts` / `motion-catalog.ts` / `copy-rules.catalog.ts`。
2. **升版本号**：L2 → `DESIGN_PROMPT_VERSION`；画面理解 → `SCENE_ANALYSIS_PROMPT_VERSION`。否则旧缓存会被继续沿用。
3. 重跑 `export-prompts.mts` / `export-catalogs.mts`，更新 `prompts/*.md`。
4. 跑测试：`pnpm --filter @marketing-photo/backend test`（88 例，其中 `design-spec.test.ts` 覆盖夹取与拦截规则）。
5. 用至少 3 张不同题材素材真机各跑一次，记录：耗时、issues 数、文案是否可用、版式是否可接受。

## 6. 已知的提示词弱点（下一阶段改进方向）

| 弱点 | 现象 | 改进方向 |
|---|---|---|
| 规则全靠字符串堆叠 | 规则越长，遵循度越低；新增一条常常削弱另一条 | 用**知识库检索的 few-shot** 替代长规则；规则只保留硬红线 |
| 示例是手写的理想输出 | 模型会模仿示例的「形状」，不一定是当前素材的最佳形状 | 从知识库召回 3–5 个**真实案例的 spec** 作为 few-shot |
| 没有「量」的能力 | 模型无法判断这行字会不会溢出 | 见 `02-局限与增强路线.md` 的 Skill：`measure_text` / `detect_layout_conflict` |
| 单候选 | 一次输出定生死 | best-of-3 + 规则打分 + 美学打分 |
| 文案评价无法闭环 | 人工改了什么，系统不知道 | 人工最终稿回流知识库（偏好样本） |
