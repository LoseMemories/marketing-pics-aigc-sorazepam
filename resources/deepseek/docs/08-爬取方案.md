# 爬取方案 · Codex 任务书（v2.0）

> 本文档给 **Codex（另一个编码 Agent）** 执行，自包含、不依赖上下文。
> Codex 产出 `crawl-raw/` 文件夹，交回后由**落库方**完成标签化与入库。
> v2.0 变更：新增「设计成品类」站点（MotionSites / Awwwards / 杂志封面 / 公告牌海报）；新增**内容质量筛选**规则；`raw.json` 增加 `isDesigned` 与 `popularity`。

---

## 0. 分工（为什么这样拆）

| 角色 | 职责 | 输出 |
|---|---|---|
| **Codex** | 选站、按质量规则抓取、下载图、提取站点元数据 | `crawl-raw/` 文件夹（见 §5） |
| **落库方** | 标签归一化、生成语义标签与意图、校验、入库 | 知识库记录（`docs/06` 的 DesignCase） |

**边界**：Codex 不碰语义标签生成、不做 facet 分类；只原样搬运站点信息 + 一个 `topic` 业务字段 + 一个 `isDesigned` 粗判标记。

## 1. 采集范围

### 1.1 两类内容（关键：优先「带设计」的）

| 类 | 含义 | 供给 KB 什么 | 优先级 |
|---|---|---|---|
| **A 设计成品类** | 已有排版/文案/版式的内容（封面、海报、hero、banner） | 设计内容 + 示例图（更全） | **优先** |
| **B 摄影素材类** | 摄影/打卡/穿搭/旅行/商品的裸图 | 主图特征 + 示例图（设计内容由落库方补写） | 其次 |

### 1.2 采集主题（`topic` 受控值）

**B 摄影素材类**：`摄影` / `打卡` / `穿搭` / `旅行` / `商品`
**A 设计成品类**：`杂志封面` / `海报演出` / `网页设计`

### 1.3 主题 → 垂类映射（落库方用，Codex 仅供参考）

| topic | vertical（默认） | 备注 |
|---|---|---|
| 旅行 | `旅行攻略` | 直接映射 |
| 穿搭 | `穿搭时尚` | 直接映射 |
| 打卡 | `探店打卡` | 直接映射 |
| 商品 | `商品带货` | 直接映射 |
| 摄影 | 视主体而定 | 人像→穿搭/旅行；风景→旅行；静物→商品 |
| 杂志封面 | `穿搭时尚`（时尚杂志）或 `演出音乐`（音乐杂志） | `platform=magazine-cover` |

> 注意：上表 `vertical` 是**默认值**，最终一条案例的 `vertical` 是**多值数组**（可同时属于多个垂类，如 `["穿搭时尚","探店打卡"]`）。Codex 不产 facets，只填 `topic`；多值归类由落库方完成。

## 3. 内容质量筛选（**不是随便爬**，重点）

1. **只爬「热度高 / 评价高 / 官方精选」**，禁止随机搜索结果：
   - Unsplash/Pexels/Openverse：只用 `featured`/`editorial`/`popular` 集合，或按 `downloads`/`likes` 降序取前 N。
   - Awwwards：只爬 `Site of the Day` / `Site of the Month` / `Honorable Mention`。
   - Dribbble：只爬 `popular shots`（高 likes）；Behance：只爬 `curated`（高 appreciations）。
   - MotionSites：官方精选库本身即 curated，全量。
   - 杂志封面：正式出版的封面（天然精选）。
   - Instagram/Pinterest：高互动（likes/saves），优先官方/品牌账号，不要爬零互动小号。
2. **必须带设计**（A 类默认满足；B 类需判定）：
   - `isDesigned=true`：画面含排版/文案/版式元素（封面、海报、hero、带字营销图）。
   - `isDesigned=false`：纯风景/纯人像裸图（仍可入 KB，但 `design` 由落库方补写）。
3. **质量信号要落进 `raw.json`**（§5.2 的 `popularity` 字段），供落库方排序。

---

## 4. 抓取规范

1. **robots.txt 优先**：每站先读；`Disallow` 通用爬虫或明确禁 AI 爬虫（如 Elle）的**不爬**。
2. **限速**：同站间隔 ≥ 1s，失败指数退避（1s/2s/4s，最多 3 次）；单站单日 ≤ 500 条。
3. **API 优先**：有 API 用 API（Unsplash/Pexels/Openverse），拿 download URL 下载；无 API 再解析 HTML（`og:image`/`img`）。
4. **设计成品用截图**：Awwwards/Lapa/MotionSites/Billboard 的「图」是网页渲染结果，用 headless（Playwright/Puppeteer）截首屏或全页存 PNG。
5. **杂志封面只存缩略图**：长边 ≤ 512px，`license=reference-only`。
6. **去重**：按图片 URL 或内容 hash（SHA-256 前 16 位）去重。
7. **命名**：目录名 `<site>_<topic>_<4位序号>`，如 `awwwards_网页设计_0001`、`unsplash_旅行_0001`。
8. **记录溯源**：每条记 `url` + `capturedAt` + `license`。

## 5. 产出物：`crawl-raw/` 文件夹（Codex 必须遵守）

### 5.1 目录结构

```
crawl-raw/
├── manifest.json
└── cases/
    ├── unsplash_旅行_0001/
    │   ├── image.jpg              # 原图（必填；杂志封面用缩略图即可）
    │   ├── thumb.webp             # 缩略图（可选，长边 ≤ 512px）
    │   └── raw.json               # 站点原始元数据（必填）
    └── awwwards_网页设计_0007/
        ├── image.png              # headless 截图
        └── raw.json
```

### 5.2 `raw.json` 契约（每条案例一个）

```jsonc
{
  "topic": "旅行",                          // 必填：§1.2 的 8 个受控值之一
  "site": "unsplash",                       // 必填：§2 站点表 slug
  "url": "https://unsplash.com/photos/xxx", // 必填：原图/详情页 URL
  "title": "Mountain lake at sunrise",      // 可空：站点给的标题
  "description": "站点给的描述/alt 文本",    // 可空
  "author": "作者/账号名",                  // 可空
  "category": "travel",                     // 可空：站点自带分类
  "siteTags": ["travel", "mountain"],       // 可空数组：站点自带标签，**原样不归一化**
  "isDesigned": true,                       // 可选：是否带设计（有排版/文案/版式）；A 类默认 true
  "popularity": {                           // 可选：热度/评价信号，供排序
    "award": "site-of-the-day",             // site-of-the-day | site-of-the-month | featured | editorial | curated | null
    "likes": 1234, "downloads": 500, "views": 8900
  },
  "width": 4000, "height": 3000,            // 必填：像素
  "license": "unsplash-license",            // 必填：见 §5.3
  "capturedAt": "2026-10-26T05:40:00+08:00" // 必填：ISO8601
}
```

> Codex 不翻译、不归一化 `title/description/category/siteTags`；只判定 `topic` 和 `isDesigned`。

### 5.3 许可值（`license` 受控）

| 值 | 含义 |
|---|---|
| `unsplash-license` / `pexels-license` | 对应站点许可 |
| `cc0` / `cc-by` / `cc-by-sa` | Creative Commons |
| `reference-only` | 仅个人参考、不商用（Instagram/Pinterest/Dribbble/Behance/500px/杂志/海报/Billboard） |

### 5.4 `manifest.json`

```jsonc
{
  "crawlerVersion": 2,
  "createdAt": "2026-10-26T06:00:00+08:00",
  "total": 400,
  "bySite": { "unsplash": 120, "awwwards": 40, "vogue": 30, "dribbble": 60, "billboard": 30 },
  "byTopic": { "旅行": 80, "穿搭": 70, "打卡": 50, "摄影": 60, "商品": 60, "杂志封面": 40, "海报演出": 40 },
  "notes": "失败站点 / 缺字段项说明"
}
```

## 6. 标签化流程（落库方执行，Codex 不碰）

1. **站点元数据 → 受控 facet**：`site`/`category`/`siteTags` 归一化到 `docs/06` §4.1 的 `facets`；`topic`→`vertical`（§1.3）。
2. **LLM 生成语义层**：看 `image` + `title/description`，生成 `semanticTags` + `intent`。
3. **校验夹取**：facets 枚举夹取；三元一致性检查；`isDesigned=false` 的 B 类案例，`design.description` 由落库方补写。

---

## 7. 验收标准

| 项 | 要求 |
|---|---|
| 数量 | 每主题 ≥ 40 条，总 ≥ 300 条 |
| 质量 | A 类（设计成品）占比 ≥ 30%；`popularity` 填充率 ≥ 80% |
| 字段完整 | `raw.json` 必填字段 100% 有值 |
| 图片可用 | 每案例 `image.<ext>` 存在可打开，宽高一致 |
| 去重 | 无重复 URL/图片 |
| 溯源 | `url` + `capturedAt` + `license` 齐全 |

---

## 8. 风险与红线

1. **版权**：网页/社媒/杂志/海报图有版权；`reference-only` 仅个人本地参考、不公开传播、不商用；保留 `url`/`capturedAt`/`license`。
2. **反爬**：小红书/Instagram/Pinterest/Billboard 有反爬；抓不到就跳过，不硬破、不绕登录。
3. **明确禁爬**：`robots.txt` 禁 AI 爬虫的站点（如 Elle）不爬。
4. **API key**：Unsplash/Pexels 需 key；Openverse 免 key 兜底；key 不进交付产物。
