# 局限与增强路线（一页速查）

> 这份表是 `00-产品PRD.md` 与 `01-技术方案.md` 的浓缩版。**给 Harness 的第一优先级输入：先看这张表。**

## 一、结论先行

现有系统 = **规则引擎（L1/L3）+ 单次 LLM（L2）+ Canvas 叠加渲染**。
它能把结果做到「不出错、可解释、可复现」，但上限是「干净但中庸的排版」。

要跨过这个上限，需要三件现在没有的东西：

1. **多模态设计知识库** —— 让模型「见过好设计」，并能被检索注入、被人工最终稿回流。
2. **设计师 Skill** —— 让模型能「量字、查对比度、查冲突、试渲染、打分」，而不是靠语义猜。
3. **照片合成 MCP** —— 让系统从「在照片上贴字」升级为「真的合成一张图」（分割/抠图/光影/修补/重定位）。

## 二、局限 → 根因 → 影响 → 需要的新技术 → 验收

| # | 局限 | 根因 | 影响 | 需要的新技术 | 验收标准 |
|---|---|---|---|---|---|
| 1 | 排版靠估算，不是真实字体度量 | 服务端无 `measureText`，用「字符数 × 字号」估宽高 | 长句/中英混排/旋转标题偶发溢出、块间挤 | 字体度量（node-canvas / opentype.js）+ 真实字体资产 | 千例回归中文字盒溢出率 < 1% |
| 2 | 主体边界只有 20 点粗多边形 | 让视觉模型「描边」，点数一多就慢且贵（20 点 23s / 100 点 75s） | 描边效果抖动；重叠混色边界粗糙 | 分割模型（SAM 系 / 商用抠图 API）替代模型描边 | 边界与真实轮廓 IoU ≥ 0.9 |
| 3 | 只能叠加，不能合成 | 渲染层是 Canvas 2D，没有分割/光照/修补能力 | 构图完全迁就原图；无「光影统一」的高级效果 | 照片合成 MCP：segment / matting / relight / shadow / inpaint / composite / **relocate** | 能产出「主体重定位 + 光影匹配」的成图 |
| 4 | 单次生成，无候选比较、无自评 | `temperature=0` 单发，没有 best-of-n、没有 critic | 偶发审美塌陷无处拦截；改进只能碰运气 | 多候选生成 + 规则打分 + 多模态美学打分 | 3 候选里 ≥2 个无需改文案，≥1 个无需改版式 |
| 5 | 没有设计知识库 | 所有约束写在提示词字符串里 | 「好版式」不可检索、不可复用；提示词越加越臃肿，遵循度反而下降 | 多模态设计知识库（结构化 spec + 视觉/文本向量 + 三级检索），人工最终稿回流 | 同场景召回的案例被人工认可率 ≥ 70% |
| 6 | 设计师没有工具 | L2 只能「说」，不能「量」 | 模型对「这行长不长、这块挤不挤」只能猜 | 设计师 Skill：`measure_text` / `check_contrast` / `detect_layout_conflict` / `render_preview` / `query_design_kb` / `score_layout` | skill 修正后 issues 率 ≤ 10% |
| 7 | 没有品牌资产与账号一致性 | 系统不知道品牌色/字体/口吻/禁用词 | 做不了账号级风格统一，做不了「像这个品牌」 | 品牌资产（Brand Kit）+ 品牌约束注入 + 一致性打分 | 同账号 5 图风格一致性人评 ≥ 4/5 |
| 8 | 文案只有一段事实资料 | 只能读 `selfies/<key>.md` | 无法接商品库/SKU/活动日历/历史爆款 | 内容侧 RAG（商品库 + 活动 + 爆款文案库）+ 实体对齐校验 | 文案事实错误率 < 2% |
| 9 | 无导出管线 | 只有浏览器内 Canvas | 交付不出物料（无 PNG/MP4/多尺寸） | 同构渲染（浏览器 + node-canvas/skia）+ ffmpeg 合成 + 多尺寸重解算 | 预览与导出像素级一致；3 尺寸 30s 内完成 |
| 10 | 同步单进程 | 请求内等 20s + 18s | 并发一高就排队；失败无法续跑 | 队列（BullMQ/pg-boss）+ 幂等键 + SSE 进度 | 20 并发下 P95 ≤ 45s，无任务丢失 |
| 11 | 无观测与成本核算 | 没有指标表 | 不知道钱花在哪、哪一步最常失败 | `generation_runs` 打点表（耗时/token/issues/人工改动） | 有可用看板，能按提示词版本对比 |
| 12 | 无评测集 | 改提示词只能人眼看 | 无法判断「改好了还是改坏了」 | 评测集（≥50 素材 + 参考输出）+ 自动指标 + blind test | 每次改提示词都有回归报告 |
| 13 | 无审美/合规审核 | 无审核通道 | 肖像/品牌/价格/功效风险 | 审核通道 + 禁用词 + 人像模糊开关 + 免责声明 | 上线素材 100% 过审核门 |

## 三、优先级建议（按「性价比」排序）

**第一梯队（低风险高收益，先做）**
1. 真实字体度量（#1）—— 纯工程，立刻提升排版稳定性。
2. 评测集 + 自动指标（#12）—— 没有它，后面所有改动都是盲改。
3. 3 候选 + 规则打分（#4 的规则部分）—— 复用现有 validator，几乎零新依赖。

**第二梯队（需要新依赖，收益明确）**
4. 分割模型替代 20 点多边形（#2）—— 描边与重叠混色立刻变好看。
5. 设计师 Skill（#6）—— 与 #1 复用同一套度量，边际成本低。
6. 导出管线（#9）—— 让成果能交付。

**第三梯队（重投入，先做小样验证）**
7. 多模态设计知识库（#5）—— 需要案例资产与向量库；建议先做 300 例内部库。
8. 照片合成 MCP（#3）—— 先验证「重定位/光影」收益，再决定是否全量。
9. 品牌资产（#7）与内容侧 RAG（#8）—— 依赖业务侧数据准备。

## 四、判断「该不该上新技术」的三条标准

1. **它是否降低了「不确定性」？** 例如字体度量把「宽度猜」变成「宽度算」，就是确定性的提升。
2. **它是否能被单测/评测集衡量？** 不能衡量的新能力，迟早会变成新的技术债。
3. **它是否破坏了「L2 不产数值」的约定？** 任何新能力都应落在「设计语汇 + 确定性解算」的形状上；如果它要求模型直接吐坐标，就说明接错了位置。
