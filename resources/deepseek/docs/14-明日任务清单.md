## 1. 抓取动漫海报 / 漫画封面 100 张

**目标**：20 部作品 × 5 张，覆盖不同画风。

**作品池（建议）**
| 画风类型 | 作品 |
|---|---|
| 少年热血 | 海贼王、火影忍者、死神（境界）、龙珠、全职猎人 |
| 风格化/武士 | 混沌武士、银魂、浪客剑心 |
| 现代/都市 | 间谍过家家、咒术回战、电锯人 |
| 少女/奇幻 | 美少女战士、魔法少女小圆、葬送的芙莉莲 |
| 硬核/科幻 | 攻壳机动队、EVA、星际牛仔 |
| 剧场/实验 | 你的名字、千与千寻、乒乓 |

**来源优先级**
1. 官方剧场版/蓝光海报（分辨率高、无水印）
2. AniList / MyAnimeList 封面 API（结构化、可直接拉）
3. 豆瓣条目海报（兜底）

**产出要求**
- 尺寸 ≥ 500px 长边，统一存 `backend/data/inspiration/anime/`
- 命名：`anime_<作品拼音>_<序号>.webp`
- 每部 5 张，尽量覆盖：主视觉海报 / 群像 / 单人 / 剧场版 / 漫画封面

**风险**：版权仅限内部素材研究用；部分官方图是 CDN 防盗链，需要带 referer。

## 2. 抓取电商店铺宣传图

**关键约束**：**不是商品详情页的图**，是店铺首页 / 活动页的宣传图（banner、主视觉、系列企划）。

**品牌 × 品类矩阵**

| 品类 | 品牌 |
|---|---|
| 相机 | 佳能、理光、富士 |
| 手机 / 电脑 | 苹果、小米、华为 |
| 服饰 | Zara、UR、拉夫劳伦、Coach |
| 首饰 | 梵克雅宝、apm、周大福 |
| 户外 | 添柏岚、The North Face、始祖鸟 |
| 眼镜 | 木九十、JINS |
| 美妆 | 雅诗兰黛、YSL、Tom Ford |

**目标数量**：每品牌 5–8 张，合计约 100 张。

**风险（最高）**
- 淘宝/京东/得物有登录态、签名参数、滑块验证；得物最严
- 直接抓详情页图片会拿到商品白底图，**不符合需求**
- 备选路径：品牌官网首页轮播 / 官方微博 / 官方小红书 / 天猫旗舰店（浏览器登录后手工翻页截图）

**建议做法**
1. 先用品牌官网 + 官方社媒（可公开访问、无反爬）拿到 60–70%
2. 剩余缺口再用浏览器人工登录天猫/京东补齐
3. 全部记录来源 URL，便于追溯

**目录**：`backend/data/inspiration/commerce/`，命名 `commerce_<品牌>_<品类>_<序号>.webp`

## 3. Linux 部署 / 本地模拟

**依赖现状**
- Node 24 + pnpm（backend Fastify、frontend webpack）
- Python 3.9 + torch + SAM（`sam_vit_b.pth` 375MB）+ EasyOCR（模型 ~100MB）
- 数据目录 `backend/data`（inspiration 70MB + live-assets 363MB）

**方案 A：Docker Compose（推荐）**
- 三个服务：`backend`、`frontend`、`python-worker`
- 模型权重与大文件**不打进镜像**，用 volume 挂载
- 验收：`docker compose up -d` 后 `:3000` 与 `:5173` 可访问，跑通一张图完整分析

**方案 B：本地 Linux 模拟**
- UTM / Parallels 起一台 Ubuntu 22.04，按方案 A 的 Dockerfile 手动装
- 适合先验证「换机器能不能跑起来」，不追求生产化

**待确认**：有没有实际服务器？规格（CPU/内存/有无 GPU）？GPU 会显著加快 SAM + OCR。

## 4. 工作台 StepLine 改造：主图检测（不含文案）

**现状**：`AiDesignPanel.vue` 的 `stageDefs` 是四步 —— 画面理解 / L1 构图 / L2 设计师 / L3 Canvas。
第 1 步目前走 `analyze-scene`（design-assistant 自己的场景分析），与灵感库的管线不一致。

**目标**：第 1 步换成与工作流一致的主图检测，**去掉文案探查**（原素材本身没有文案）。

**新第一步应包含**
- 主体检测（SAM）+ 主体数量
- 主体热区（10×10）与色块分布
- 主色 / 辅色 / 色调
- 构图焦点、留白率

**不包含**
- OCR / 文案层级 / 文案热区 / 文案颜色

**做法**
1. 复用 `workflow-analyze.py` 里的 SAM + 热区 + `design_fill` 配色逻辑，抽一个「无文案」入口
2. 输出结构对齐前端已有的 `subjectRegions` / `subjectOutlines`，避免重写渲染
3. `stageDefs[0].title` 改「主图检测」，按钮文案改「检测主体 / 重新检测」

**验收**
- 上传一张无文案素材，第 1 步完成后显示：主体数、热区图、配色、构图焦点
- 页面不出现任何文案相关区块
